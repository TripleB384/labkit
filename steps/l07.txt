LESSON 7: LVM   (Linux+ objective 1.3)
============================================================
Setup needed first: sudo bash ~/labkit/u1-disks.sh

TICKET PP-107
From:    Jordan Kim, Web Developer
Subject: The uploads folder keeps running out of space

  Customer photo uploads keep filling the disk, and I'm tired of
  downtime when we resize. Marcus says LVM lets us grow storage while
  it's in use. Can you set up a volume for uploads and show me it can
  grow without unmounting?

--- Step 1 ----------------------------------------
Load the test disk names. Prepare DISK2 and DISK3 for LVM as
physical volumes.
  $ source /tmp/disks.env
  $ sudo pvcreate $DISK2 $DISK3
  You should see:
    Physical volume "/dev/loopN" successfully created. (x2)
  What each part means:
    source                      = Run a file in YOUR current shell, so its variables stay
    /tmp/disks.env              = file the storage setup wrote, holding DISK1-DISK5
    sudo                        = Run the rest as root (admin)
    pvcreate                    = Prepare a disk for LVM (physical volume)
    $DISK2                      = your fake disk 2 (from /tmp/disks.env)
    $DISK3                      = your fake disk 3 (from /tmp/disks.env)

--- Step 2 ----------------------------------------
Confirm both disks are ready for LVM.
  $ sudo pvs
  You should see:
    Two PVs, about 300m each. The VG column is empty (not in a pool yet).
  What each part means:
    sudo                        = Run the rest as root (admin)
    pvs                         = List physical volumes

--- Step 3 ----------------------------------------
Start a storage pool (volume group) with just DISK2 for now.
  $ sudo vgcreate vg_lab $DISK2
  $ sudo vgs
  You should see:
    vg_lab  1 PV  ... VSize about 296m
  Why:
    A few MB go to LVM's own metadata.
  What each part means:
    sudo                        = Run the rest as root (admin)
    vgcreate                    = Create an LVM volume group (storage pool)
    $DISK2                      = your fake disk 2 (from /tmp/disks.env)
    vgs                         = List volume groups

--- Step 4 ----------------------------------------
Carve out a 100 MB volume for Jordan's uploads.
  $ sudo lvcreate -n lv_data -L 100M vg_lab
  $ sudo lvs
  You should see:
    lv_data  vg_lab  -wi-a-----  100.00m
  What each part means:
    sudo                        = Run the rest as root (admin)
    lvcreate                    = Create an LVM logical volume
    -n lv_data                  = name for the new volume
    -L 100M                     = size (100M)
    lvs                         = List logical volumes

--- Step 5 ----------------------------------------
Jordan asks which device path to use. Show him both names point to
the same volume.
  $ ls -l /dev/vg_lab/
  $ ls -l /dev/mapper/ | grep lv_data
  You should see:
    lv_data -> ../dm-0  (links to the same dm device)
  What each part means:
    ls                          = List files
    -l                          = long format: permissions, owner, size, date
    /dev/vg_lab/                = your LVM volume (volume group / logical volume)
    /dev/mapper/                = device-mapper names for LVM volumes
    |                           = pipe: send the output of the left command into the next one
    grep                        = Search text for lines matching a pattern
    lv_data                     = the pattern to search for

--- Step 6 ----------------------------------------
Format the volume and mount it where uploads will live.
  $ sudo mkfs.ext4 -q /dev/vg_lab/lv_data
  $ sudo mkdir -p /mnt/data
  $ sudo mount /dev/vg_lab/lv_data /mnt/data
  $ df -h /mnt/data
  You should see:
    Size about 90M, mounted on /mnt/data
  What each part means:
    sudo                        = Run the rest as root (admin)
    mkfs.ext4                   = Create an ext4 filesystem
    -q                          = quiet
    /dev/vg_lab/lv_data         = your LVM volume (volume group / logical volume)
    mkdir                       = Make a folder
    -p                          = make every missing parent folder too
    /mnt/data                   = /mnt = a common place to mount things
    mount                       = Attach a filesystem to a folder
    df                          = Disk free: space used and left on each filesystem
    -h                          = human-readable sizes (M, G)

--- Step 7 ----------------------------------------
Uploads are filling up. Grow the volume by 100 MB while it stays
mounted.
  $ sudo lvextend -r -L +100M /dev/vg_lab/lv_data
  $ df -h /mnt/data
  You should see:
    Size now about 180–190M. No unmount needed.
  Why:
    -r runs resize2fs for you. Without -r the LV grows but df still
    shows the old size.
  What each part means:
    sudo                        = Run the rest as root (admin)
    lvextend                    = Grow a logical volume
    -r                          = also resize the filesystem on it
    -L +100M                    = new size (a + means add that much)
    /dev/vg_lab/lv_data         = your LVM volume (volume group / logical volume)
    df                          = Disk free: space used and left on each filesystem
    -h                          = human-readable sizes (M, G)
    /mnt/data                   = /mnt = a common place to mount things

--- Step 8 ----------------------------------------
Jordan wants another 200 MB. Try it and see what the pool says.
  $ sudo lvextend -r -L +200M /dev/vg_lab/lv_data
  You should see:
    Insufficient free space ...
  Why:
    The pool (VG) is almost out of space.
  What each part means:
    sudo                        = Run the rest as root (admin)
    lvextend                    = Grow a logical volume
    -r                          = also resize the filesystem on it
    -L +200M                    = new size (a + means add that much)
    /dev/vg_lab/lv_data         = your LVM volume (volume group / logical volume)

--- Step 9 ----------------------------------------
Add DISK3 to the pool, then give Jordan his 200 MB.
  $ sudo vgextend vg_lab $DISK3
  $ sudo vgs
  $ sudo lvextend -r -L +200M /dev/vg_lab/lv_data
  $ df -h /mnt/data
  You should see:
    vg_lab now has 2 PVs, about 592m.
    The LV grows. df shows about 370–380M.
  What each part means:
    sudo                        = Run the rest as root (admin)
    vgextend                    = Add a disk to a volume group
    $DISK3                      = your fake disk 3 (from /tmp/disks.env)
    vgs                         = List volume groups
    lvextend                    = Grow a logical volume
    -r                          = also resize the filesystem on it
    -L +200M                    = new size (a + means add that much)
    /dev/vg_lab/lv_data         = your LVM volume (volume group / logical volume)
    df                          = Disk free: space used and left on each filesystem
    -h                          = human-readable sizes (M, G)
    /mnt/data                   = /mnt = a common place to mount things

--- Step 10 ----------------------------------------
Marcus asks which physical disks the uploads now live on. Show him.
  $ sudo pvs
  $ sudo lvdisplay /dev/vg_lab/lv_data | head -12
  You should see:
    Both PVs now show used space. lvdisplay shows LV Size about 400 MiB.
  What each part means:
    sudo                        = Run the rest as root (admin)
    pvs                         = List physical volumes
    lvdisplay                   = Show logical volume details
    /dev/vg_lab/lv_data         = your LVM volume (volume group / logical volume)
    |                           = pipe: send the output of the left command into the next one
    head                        = Show the first lines of a file (default 10)
    -12                         = show the first 12 lines

STUCK?
  * Cannot use /dev/loopN: device is partitioned
      That disk still has a partition table. Run: sudo wipefs -a $DISK2
  * $DISK2 is empty
      source /tmp/disks.env
  * Volume group vg_lab not found
      Check the spelling with sudo vgs. Or run the storage cleanup + setup
      and start this lab again.
  * Want a fresh start
      sudo bash ~/labkit/u1-clean.sh, then sudo bash ~/labkit/u1-disks.sh

BEFORE YOU LEAVE: Leave lv_data mounted. Lesson 8 uses it.

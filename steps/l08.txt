LESSON 8: Mounting & fstab   (Linux+ objective 1.3)
============================================================
Setup needed first: sudo bash ~/labkit/u1-disks.sh

GOAL: Use mount options to block programs, lock a filesystem read-only, and add a safe fstab entry.

--- Step 1: Check that lv_data from Lesson 7 is mounted.
  $ findmnt /mnt/data
  You should see:
    /mnt/data  /dev/mapper/vg_lab-lv_data  ext4  rw,relatime
  Why: Nothing printed? Run: sudo mount /dev/vg_lab/lv_data /mnt/data

--- Step 2: Find it in the kernel's live mount list.
  $ grep /mnt/data /proc/mounts
  You should see:
    /dev/mapper/vg_lab-lv_data /mnt/data ext4 rw,relatime 0 0

--- Step 3: Copy the lab script there and run it.
  $ sudo cp ~/linuxlab/scripts/hello.sh /mnt/data/
  $ /mnt/data/hello.sh
  You should see:
    Hello from the lab script!

--- Step 4: Remount with noexec and try again.
  $ sudo mount -o remount,noexec /mnt/data
  $ /mnt/data/hello.sh
  $ findmnt /mnt/data
  You should see:
    Permission denied
    OPTIONS: rw,noexec,relatime
  Why: The file is executable, but the mount blocks it. Common on /tmp for security.

--- Step 5: Turn exec back on.
  $ sudo mount -o remount,exec /mnt/data
  $ /mnt/data/hello.sh
  You should see:
    Hello from the lab script!

--- Step 6: Make it read-only, try to write, then undo.
  $ sudo mount -o remount,ro /mnt/data
  $ sudo touch /mnt/data/test.txt
  $ sudo mount -o remount,rw /mnt/data
  You should see:
    touch: cannot touch '/mnt/data/test.txt': Read-only file system

--- Step 7: See 'target is busy', then fix it.
  $ cd /mnt/data
  $ sudo umount /mnt/data
  $ cd ~
  $ sudo umount /mnt/data
  $ findmnt /mnt/data
  You should see:
    umount: /mnt/data: target is busy.
    ...then after cd ~ it works, and findmnt prints nothing.

--- Step 8: Back up fstab, then add an entry with noatime + nofail.
  $ sudo cp /etc/fstab /etc/fstab.bak
  $ echo "/dev/vg_lab/lv_data /mnt/data ext4 defaults,noatime,nofail 0 2" | sudo tee -a /etc/fstab
  You should see:
    The line prints back.
  Why: Real servers use UUID=... from blkid. The device path is fine for this lab.

--- Step 9: Test the fstab with mount -a.
  $ sudo mount -a
  $ findmnt /mnt/data
  You should see:
    /mnt/data mounted again, OPTIONS include noatime
  Why: No errors = safe to reboot. An error here = fix fstab NOW.

--- Step 10: Restore the original fstab.
  $ sudo cp /etc/fstab.bak /etc/fstab
  $ tail -3 /etc/fstab
  You should see:
    The vg_lab line is gone.

--- Step 11: Read-only practice: network mount syntax. Just read these.
    # NFS
  $ sudo mount -t nfs 192.168.1.50:/exports/files /mnt/nfs
    # SMB / CIFS
  $ sudo mount -t cifs //192.168.1.60/share /mnt/smb -o username=bob
  You should see:
    Nothing to run. There's no file server in your lab VM.
  Why: Exam keywords: NFS = Linux shares (server:/path). SMB/CIFS/Samba = Windows shares (//server/share).

STUCK?
  * target is busy: Something (often your own terminal) is inside that folder. cd ~ and try again.
  * mount -a shows an error: Restore right away: sudo cp /etc/fstab.bak /etc/fstab
  * special device does not exist: Lesson 7 wasn't finished, or the VG is inactive. Try: sudo vgchange -a y vg_lab

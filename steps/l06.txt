LESSON 6: RAID   (Linux+ objective 1.3)
============================================================
Setup needed first: sudo bash ~/labkit/u1-disks.sh

TICKET PP-106
From:    Rosa Lima, Owner
Subject: Make sure we never lose the invoices again

  Last year a dead hard drive almost cost us a month of invoices. I
  want our invoice storage mirrored, so if one drive dies we lose
  nothing. Marcus says you can set that up. Please prove to me that it
  actually survives a failure.

--- Step 1 ----------------------------------------
Load the test disk names and make sure no RAID array exists yet.
  $ source /tmp/disks.env
  $ cat /proc/mdstat
  You should see:
    Personalities : ...
    unused devices: <none>

--- Step 2 ----------------------------------------
Build the mirror (RAID 1) from DISK4 and DISK5 for the invoice
storage.
  $ sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 $DISK4 $DISK5
  You should see:
    It may warn about boot metadata and ask 'Continue creating array?' Type y and Enter.
    Then: mdadm: array /dev/md0 started.

--- Step 3 ----------------------------------------
Check that both drives are in sync.
  $ cat /proc/mdstat
  You should see:
    md0 : active raid1 loopN[1] loopN[0]
    ... [2/2] [UU]
  Why:
    You may see a resync % at first. Wait a few seconds and run it
    again.

--- Step 4 ----------------------------------------
Get the full array details for Rosa's records.
  $ sudo mdadm --detail /dev/md0
  You should see:
    Raid Level : raid1
    State : clean
    Active Devices : 2

--- Step 5 ----------------------------------------
Format the mirror, mount it, and save an invoice file on it.
  $ sudo mkfs.ext4 -q /dev/md0
  $ sudo mkdir -p /mnt/raid
  $ sudo mount /dev/md0 /mnt/raid
  $ echo "invoice data" | sudo tee /mnt/raid/data.txt
  You should see:
    invoice data

--- Step 6 ----------------------------------------
The real test for Rosa: kill one of the drives on purpose. Are the
invoices still there?
  $ sudo mdadm /dev/md0 --fail $DISK5
  $ cat /proc/mdstat
  $ cat /mnt/raid/data.txt
  You should see:
    loopN(F) ... [2/1] [U_]
    Your file still reads: invoice data
  Why:
    [U_] = degraded. The mirror kept your data alive.

--- Step 7 ----------------------------------------
Swap in a "new" drive and watch the mirror rebuild itself.
  $ sudo mdadm /dev/md0 --remove $DISK5
  $ sudo mdadm /dev/md0 --add $DISK5
  $ cat /proc/mdstat
  You should see:
    recovery = xx% ... then later [2/2] [UU]

--- Step 8 ----------------------------------------
Test passed. Unmount and shut the array down.
  $ sudo umount /mnt/raid
  $ sudo mdadm --stop /dev/md0
  You should see:
    mdadm: stopped /dev/md0

STUCK?
  * mdadm: command not found
      sudo apt install -y mdadm
  * Device or resource busy
      The disk is in use. Check lsblk. Running the storage cleanup + setup
      gives you fresh disks.
  * Error about the md driver
      Some lab VMs block software RAID. Read the steps and expected output
      instead. The quiz still counts.

DONE? Ticket PP-106 closed.
  Rosa has her proof: one drive died and the invoices didn't care.

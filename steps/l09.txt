LESSON 9: Filesystems & Inodes   (Linux+ objective 1.3)
============================================================
Setup needed first: sudo bash ~/labkit/u1-disks.sh

TICKET PP-109
From:    Jordan Kim, Web Developer
Subject: URGENT: "No space left" but the disk is empty?!

  The thumbnail server says "No space left on device," but df shows
  the disk is barely used. I'm losing my mind. Can you figure out
  what's going on? Also, while you're in there, the reports server
  needs more room and it runs XFS.

--- Step 1 ----------------------------------------
Start your investigation. Compare free space AND free inodes on the
main disk.
  $ df -h /
  $ df -i /
  $ du -sh ~/linuxlab
  You should see:
    Size/Used/Avail, then Inodes/IUsed/IFree, then the folder size (a few KB).
  What each part means:
    df                          = Disk free: space used and left on each filesystem
    -h                          = human-readable sizes (M, G)
    -i                          = show inodes instead of space
    du                          = Disk usage: how much space files/folders use
    -sh                         = -s summary: one total per item; -h human-readable sizes
    ~/linuxlab                  = ~ = your home folder

--- Step 2 ----------------------------------------
Rebuild Jordan's problem: a small filesystem with very few inodes,
like his thumbnail server.
  $ sudo truncate -s 20M /root/disklab/tiny.img
  $ sudo mkfs.ext4 -q -F -N 64 /root/disklab/tiny.img
  $ sudo mkdir -p /mnt/tiny
  $ sudo mount -o loop /root/disklab/tiny.img /mnt/tiny
  You should see:
    No output = success.
  What each part means:
    sudo                        = Run the rest as root (admin)
    truncate                    = Set a file's size
    -s 20M                      = the new size
    mkfs.ext4                   = Create an ext4 filesystem
    -q                          = quiet
    -F                          = force, even if it looks used
    -N 64                       = how many inodes to create
    mkdir                       = Make a folder
    -p                          = make every missing parent folder too
    /mnt/tiny                   = /mnt = a common place to mount things
    mount                       = Attach a filesystem to a folder
    -o loop                     = mount options
    loop                        = mount a file as if it were a disk

--- Step 3 ----------------------------------------
Fill it with tiny files the way the thumbnail generator does, until
it breaks.
  $ for i in $(seq 1 100); do sudo touch /mnt/tiny/f$i || break; done
  You should see:
    touch: cannot touch '/mnt/tiny/f54': No space left on device
  Why:
    The exact number may differ slightly.
  What each part means:
    for                         = Loop: run the commands once for each item
    $(seq 1 100)                = $( ) runs the command inside and pastes its result here
    seq                         = Print a sequence of numbers
    ;                           = then run the next command
    do                          = start of the loop body
    sudo                        = Run the rest as root (admin)
    touch                       = Create an empty file, or update its timestamp
    /mnt/tiny/f$i               = /mnt = a common place to mount things
    |                           = pipe: send the output of the left command into the next one
    break                       = Stop the loop
    done                        = end of the loop

--- Step 4 ----------------------------------------
The mystery: why does it say full when there's space? Check both
numbers.
  $ df -h /mnt/tiny
  $ df -i /mnt/tiny
  You should see:
    df -h: Use% 1%
    df -i: IUse% 100%
  Why:
    This is inode exhaustion. Exam answer: check df -i.
  What each part means:
    df                          = Disk free: space used and left on each filesystem
    -h                          = human-readable sizes (M, G)
    /mnt/tiny                   = /mnt = a common place to mount things
    -i                          = show inodes instead of space

--- Step 5 ----------------------------------------
Run a filesystem check on it. Remember to unmount first.
  $ sudo umount /mnt/tiny
  $ sudo e2fsck -fn /root/disklab/tiny.img
  You should see:
    Pass 1 ... Pass 5, then:
    tiny.img: 64/64 files ...
  Why:
    -f = force a full check, -n = only look, change nothing.
  What each part means:
    sudo                        = Run the rest as root (admin)
    umount                      = Detach (unmount) a filesystem
    /mnt/tiny                   = /mnt = a common place to mount things
    e2fsck                      = Check an ext2/3/4 filesystem for errors
    -fn                         = -f force a full check; -n no changes, just report

--- Step 6 ----------------------------------------
Jordan asks about the links he saw in the customers folder. Make a
hard link and a symlink to compare them.
  $ cd ~/linuxlab
  $ ln customers.csv cust-hard.csv
  $ ln -s customers.csv cust-soft.csv
  $ ls -li customers.csv cust-*
  You should see:
    customers.csv and cust-hard.csv share the SAME inode number, link count 2.
    cust-soft.csv -> customers.csv has its own inode.
  What each part means:
    cd                          = Change directory (move to another folder)
    ~/linuxlab                  = ~ = your home folder
    ln                          = Make a link to a file (hard link by default)
    -s                          = symbolic link (points to the path)
    ls                          = List files
    -li
        = -l long format: permissions, owner, size, date; -i show inode
        numbers

--- Step 7 ----------------------------------------
Delete the original file. Which link still works?
  $ rm customers.csv
  $ head -2 cust-hard.csv
  $ cat cust-soft.csv
  You should see:
    Hard link still shows the data.
    cat: cust-soft.csv: No such file or directory
  Why:
    Get customers.csv back later with: bash ~/labkit/u1.sh
  What each part means:
    rm                          = Delete files
    head                        = Show the first lines of a file (default 10)
    -2                          = show the first 2 lines
    cat                         = Print a file's contents

--- Step 8 ----------------------------------------
Look at the inode details to see why the hard link survived.
  $ stat cust-hard.csv
  You should see:
    Inode: <number>   Links: 1  (it was 2 before the delete)
  What each part means:
    stat                        = Show a file's inode, size, permissions and times

--- Step 9 ----------------------------------------
Next item: set up the reports server's XFS filesystem on DISK1 and
mount it.
  $ source /tmp/disks.env
  $ sudo wipefs -a $DISK1
  $ sudo mkfs.xfs -f $DISK1
  $ sudo mkdir -p /mnt/xfsdata
  $ sudo mount $DISK1 /mnt/xfsdata
  $ df -hT /mnt/xfsdata
  You should see:
    Type: xfs, Size about 236M
  Why:
    XFS needs at least 300 MB, which is why it gets a whole fake disk.
  What each part means:
    source                      = Run a file in YOUR current shell, so its variables stay
    /tmp/disks.env              = file the storage setup wrote, holding DISK1-DISK5
    sudo                        = Run the rest as root (admin)
    wipefs                      = Erase filesystem/partition signatures
    -a                          = erase all of them
    $DISK1                      = your fake disk 1 (from /tmp/disks.env)
    mkfs.xfs                    = Create an XFS filesystem
    -f                          = force, overwrite what's there
    mkdir                       = Make a folder
    -p                          = make every missing parent folder too
    /mnt/xfsdata                = /mnt = a common place to mount things
    mount                       = Attach a filesystem to a folder
    df                          = Disk free: space used and left on each filesystem
    -hT                         = -h human-readable sizes (M, G); -T show the filesystem type

--- Step 10 ----------------------------------------
Reports need more room. The "disk" just got bigger, so grow XFS
while it stays mounted.
  $ sudo truncate -s 400M /root/disklab/disk1.img
  $ sudo losetup -c $DISK1
  $ sudo xfs_growfs /mnt/xfsdata
  $ df -hT /mnt/xfsdata
  You should see:
    data blocks changed from 76800 to 102400
    Size now about 336M
  Why:
    xfs_growfs takes the MOUNT POINT. There's no command to shrink XFS.
  What each part means:
    sudo                        = Run the rest as root (admin)
    truncate                    = Set a file's size
    -s 400M                     = the new size
    losetup                     = Manage loop devices (files acting as disks)
    -c                          = re-read the backing file's size
    $DISK1                      = your fake disk 1 (from /tmp/disks.env)
    xfs_growfs                  = Grow a mounted XFS filesystem (give it the mount point)
    /mnt/xfsdata                = /mnt = a common place to mount things
    df                          = Disk free: space used and left on each filesystem
    -hT                         = -h human-readable sizes (M, G); -T show the filesystem type

--- Step 11 ----------------------------------------
Marcus wants the ext4 settings on the uploads volume from ticket
PP-107.
  $ sudo tune2fs -l /dev/vg_lab/lv_data | grep -E "Inode count|Block size|features"
  You should see:
    Filesystem features: has_journal ... Inode count ... Block size: 4096
  What each part means:
    sudo                        = Run the rest as root (admin)
    tune2fs                     = View or change ext4 settings
    -l                          = list the superblock settings
    /dev/vg_lab/lv_data         = your LVM volume (volume group / logical volume)
    |                           = pipe: send the output of the left command into the next one
    grep                        = Search text for lines matching a pattern
    -E                          = extended regex (lets | mean OR)
    "Inode count|Block size|features"
        = the pattern to search for; | = OR

--- Step 12 ----------------------------------------
Jordan wants a super-fast scratch area for temp files. Mount one in
RAM.
  $ sudo mkdir -p /mnt/ram
  $ sudo mount -t tmpfs -o size=50M tmpfs /mnt/ram
  $ df -hT /mnt/ram
  $ sudo umount /mnt/ram
  You should see:
    tmpfs  tmpfs  50M  0  50M  0%  /mnt/ram
  What each part means:
    sudo                        = Run the rest as root (admin)
    mkdir                       = Make a folder
    -p                          = make every missing parent folder too
    /mnt/ram                    = /mnt = a common place to mount things
    mount                       = Attach a filesystem to a folder
    -t tmpfs                    = filesystem type
    -o size=50M                 = mount options
    size=50M                    = maximum size
    df                          = Disk free: space used and left on each filesystem
    -hT                         = -h human-readable sizes (M, G); -T show the filesystem type
    umount                      = Detach (unmount) a filesystem

--- Step 13 ----------------------------------------
All done. Clean up the storage lab and reset your files.

  $ sudo bash ~/labkit/u1-clean.sh
  $ bash ~/labkit/u1.sh
  You should see:
    Storage lab cleaned up ...
    Lab ready in /home/<you>/linuxlab
  What each part means:
    cd                          = Change directory (move to another folder)
    ~                           = ~ = your home folder
    sudo                        = Run the rest as root (admin)
    bash
        = Run the script in a NEW bash shell (its variables vanish when it
        ends)

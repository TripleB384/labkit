LESSON 10: Files & Directories   (Linux+ objective 2.1)
============================================================
Setup needed first: bash ~/labkit/u2.sh

TICKET PP-110
From:    Dana Okafor, Operations Manager
Subject: The shared projects folder is a mess

  Our shared projects folder is a disaster: old backups, huge videos,
  and Marcus thinks someone left a file anyone can edit. Please clean
  it up, archive the website, find what's eating space, and tell me
  what changed between the two website configs. Everything's in
  ~/linuxlab2.

--- Step 1 ----------------------------------------
Open the shared folder and take a look around.
  $ cd ~/linuxlab2
  $ ls -l
  $ ls -la projects/web
  You should see:
    configs  container  newhires.csv  projects  scripts  units
    Then the web files, including deploy.sh and secrets.txt.

--- Step 2 ----------------------------------------
Get comfortable moving around: dive into the web folder, then jump
back.
  $ cd projects/web
  $ pwd
  $ cd ../..
  $ cd -
  $ cd ~/linuxlab2
  You should see:
    /home/<you>/linuxlab2/projects/web
    ...then cd - prints that same path again.

--- Step 3 ----------------------------------------
Make an archive folder for this month, organized by year and month.
  $ mkdir -p archive/2026/oct
  $ ls -R archive
  You should see:
    archive:
    2026
    archive/2026:
    oct

--- Step 4 ----------------------------------------
Archive a copy of the website, and rename the temp cache file so
it's clearly old.
  $ cp -r projects/web archive/web-copy
  $ ls archive/web-copy
  $ mv projects/old/cache.tmp projects/old/cache.old
  $ ls projects/old
  You should see:
    The 5 web files copied.
    Then cache.tmp is now cache.old.

--- Step 5 ----------------------------------------
Remove the empty folder nobody uses. Then see what happens when you
try a folder that still has files in it.
  $ rmdir projects/empty
  $ rmdir projects/old
  You should see:
    First one works (no output).
    rmdir: failed to remove 'projects/old': Directory not empty

--- Step 6 ----------------------------------------
Find every backup file in the projects folder.
  $ find projects -name "*.bak"
  You should see:
    projects/old/notes.txt.bak
    projects/old/draft.txt.bak

--- Step 7 ----------------------------------------
Dana asks what's hogging space. Find files over 1 MB, then anything
not touched in a month.
  $ find projects -size +1M
  $ find projects -mtime +30
  You should see:
    video-promo.mp4 and backup-2025.tar
    Then: backup-2025.tar and notes.txt.bak
  Why:
    -mtime +30 means modified MORE than 30 days ago. draft.txt.bak is
    only 10 days old, so it's not listed.

--- Step 8 ----------------------------------------
Marcus's worry: find any file that ANYONE can change.
  $ find projects -type f -perm 777
  $ ls -l projects/web/secrets.txt
  You should see:
    projects/web/secrets.txt
    -rwxrwxrwx ... secrets.txt
  Why:
    777 = everyone can read, write and run it. A real admin would fix
    this right away.

--- Step 9 ----------------------------------------
Delete only the backups older than 30 days. Confirm each one.
  $ find projects -name "*.bak" -mtime +30 -exec rm -i {} \;
  $ ls projects/old
  You should see:
    rm: remove regular file 'projects/old/notes.txt.bak'? y
    Only notes.txt.bak is gone. draft.txt.bak stays.

--- Step 10 ----------------------------------------
Jordan says a file "looks weird". Check what each file really is,
ignoring the extension.
  $ file projects/web/index.html projects/web/deploy.sh projects/web/video-promo.mp4 /bin/ls
  You should see:
    ASCII text
    Bourne-Again shell script ... executable
    data
    ELF 64-bit LSB pie executable ...
  Why:
    The .mp4 is fake: just zeros. file looks at the contents, not the
    name.

--- Step 11 ----------------------------------------
Get the details on a file, and how much space each folder uses.
  $ stat projects/web/index.html
  $ du -sh projects/*
  $ df -h ~
  You should see:
    File, Size, Inode, Links, Access (0664/-rw-rw-r--) ...
    web about 5.1M, old about 2.1M
    Then your disk's size and free space.

--- Step 12 ----------------------------------------
Dana asks what changed between the old and new website configs.
Compare them three ways.
  $ diff configs/site-v1.conf configs/site-v2.conf
  $ sdiff configs/site-v1.conf configs/site-v2.conf
  $ diff -u configs/site-v1.conf configs/site-v2.conf
  You should see:
    2c2
    < listen 80
    ---
    > listen 443
    ...
    sdiff marks changes with | and new lines with >
    diff -u shows - and + lines.

--- Step 13 ----------------------------------------
Find files across the whole server fast with locate, and learn why
it can miss brand-new ones.
  $ sudo apt install -y plocate
  $ sudo updatedb
  $ locate deploy.sh
  $ touch ~/linuxlab2/brandnew.txt
  $ locate brandnew.txt
  $ sudo updatedb
  $ locate brandnew.txt
  You should see:
    Finds deploy.sh.
    brandnew.txt is NOT found the first time.
    After updatedb it is.

--- Step 14 ----------------------------------------
Someone's "using" the new-hire list. See which process has it open.
  $ tail -f newhires.csv &
  $ lsof newhires.csv
  $ kill %1
  You should see:
    COMMAND  PID  USER ... NAME
    tail     1234 you  ... newhires.csv

--- Step 15 ----------------------------------------
Marcus quizzes you: which devices are disks and which are character
devices?
  $ ls -l /dev/null /dev/zero /dev/urandom /dev/tty
  $ lsblk -d -o NAME,TYPE
  $ ls -l /dev/$(lsblk -dn -o NAME | head -1)
  You should see:
    crw-rw-rw- ... /dev/null  (c = character)
    ...
    brw-rw---- ... /dev/sda or /dev/vda  (b = block)

STUCK?
  * No such file or directory
      Run the setup first: bash ~/labkit/u2.sh (it makes ~/linuxlab2).
  * find: missing argument to -exec
      The command must end with \; (backslash, then semicolon).
  * locate: command not found
      sudo apt install -y plocate, then sudo updatedb.
  * lsof: command not found
      sudo apt install -y lsof

DONE? Ticket PP-110 closed.
  Folder cleaned, risky file flagged, configs compared. Dana's happy.

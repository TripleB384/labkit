TICKET PP-103

Subject: Get fast on the shell, then fix debug mode

  You'll live in this terminal, so let's make you quick. I'll show you
  my favorite shortcuts. Then I have a real fix for you: someone left

--- Step 1 ----------------------------------------
Marcus: "The shell remembers everything you type." Look at your
recent commands.
  $ cd ~/linuxlab
  $ history | tail -5
  You should see:
    Your last 5 commands, each with a number.

--- Step 2 ----------------------------------------
Count today's errors again, then rerun it without retyping, using
Marcus's favorite shortcut.
  $ grep -c ERROR app.log
  $ !!
  You should see:
    3
    (bash shows the command again, then) 3

--- Step 3 ----------------------------------------
You ran an awk command earlier but forgot it. Search your history
for it with Ctrl+R.
    (Press Ctrl+R, type: awk)
  You should see:
    Your last awk command appears. Enter runs it. Ctrl+G cancels.

--- Step 4 ----------------------------------------
Finance asks for average revenue per customer. Notice which math
method drops the cents.
  $ echo $((1228 / 12))
  $ echo "scale=2; 1228 / 12" | bc
  You should see:
    102
    102.33
  Why:
    $(( )) drops decimals. bc keeps them.

--- Step 5 ----------------------------------------
Make the plan prices look tidy for a quick price sheet.
  $ printf "%-10s %6.2f\n" Gold 149 Basic 59.5
  You should see:
    Gold       149.00
    Basic       59.50
  Why:
    printf reuses the format for each pair of values.

--- Step 6 ----------------------------------------
Marcus wants the unique server names on one line so he can paste
them into a ticket.
  $ sort -u servers.txt | xargs echo "Servers:"
  You should see:
    Servers: cache01 db01 web01 web02

--- Step 7 ----------------------------------------
Tired of typing ls -lh? Make a shortcut for it, then remove it.
  $ alias ll='ls -lh'
  $ ll
  $ unalias ll
  You should see:
    ll shows a long listing. After unalias, ll is gone.

--- Step 8 ----------------------------------------
Marcus explains why his settings vanished last week: he ran a script
instead of sourcing it. See the difference yourself.
  $ echo 'MYVAR=pool' > vars.sh
  $ bash vars.sh
  $ echo "[$MYVAR]"
  $ source vars.sh
  $ echo "[$MYVAR]"
  You should see:
    []
    [pool]
  Why:
    bash runs it in a separate shell, so the variable disappears. source
    runs it in yours.

--- Step 9 ----------------------------------------
Get to know this server: your home folder, your shell, and where it
looks for commands.
  $ echo $HOME $SHELL
  $ echo $PATH | tr ':' '\n'
  $ cd /tmp
  $ cd -
  You should see:
    Your home and shell, then each PATH folder on its own line. cd - jumps back to ~/linuxlab.

--- Step 10 ----------------------------------------
The vendor's support form asks for the kernel version and CPU type.
Grab both.
  $ uname -r
  $ uname -m
  You should see:
    A kernel version like 6.x.x-xx-generic
    x86_64 (or aarch64)

--- Step 11 ----------------------------------------
Now the real fix. Back up the app config first (Marcus's rule), then
open it in vim.
  $ cp config/app.conf config/app.bak
  $ vim config/app.conf
  You should see:
    The file opens. You're in Normal mode.

--- Step 12 ----------------------------------------
In vim: switch debug off, add a timezone line at the bottom, then
save and quit.
  $ :%s/debug=true/debug=false/
  $ G
  $ o
  $ timezone=UTC
    (press Esc)
  $ :wq
  You should see:
    Back at the prompt.
  Why:
    G = go to last line. o = open a new line below and switch to Insert
    mode.

--- Step 13 ----------------------------------------
Prove exactly what you changed, so Marcus can review it.
  $ diff config/app.bak config/app.conf
  You should see:
    < debug=true
    ---
    > debug=false
    plus an added timezone=UTC line

--- Step 14 ----------------------------------------
Add "fixed debug mode" to your to-do list using nano.
  $ nano todo.txt
  You should see:
    Type a new line, press Ctrl+O then Enter to save, Ctrl+X to exit.

STUCK?
  * Stuck in vim
      Press Esc a couple of times, type :q! and press Enter. That quits
      without saving.
  * vim: command not found
      Use vi instead, or run: sudo apt install -y vim
  * Ctrl+R shows the wrong command
      Press Ctrl+R again to go further back. Ctrl+G cancels.
  * nano asks 'File Name to Write'
      Just press Enter to keep the same name.

DONE? Ticket PP-103 closed.
  Debug mode is off, the change is documented, and you've got real
  shell speed now.

LESSON 15: Containers   (Linux+ objective 2.6)
============================================================
Setup needed first: bash ~/labkit/u2.sh

TICKET PP-115
From:    Jordan Kim, Web Developer
Subject: Ship the landing page in a container

  New plan: we want to ship the landing page as a container so it runs
  the same everywhere. Marcus says use Podman. Learn the basics, build
  our own image from the Containerfile in ~/linuxlab2/container, and
  show me data that survives restarts and containers that can talk to
  each other.

--- Step 1 ----------------------------------------
Install the container tool Marcus picked.
  $ sudo apt install -y podman
  $ podman --version
  You should see:
    podman version 3.4.x (Ubuntu 22.04) or 4.x / 5.x (newer)

--- Step 2 ----------------------------------------
Download a tiny Linux image to experiment with.
  $ podman pull docker.io/library/alpine
  $ podman images
  You should see:
    Writing manifest ... Storing signatures
    REPOSITORY  TAG  IMAGE ID  CREATED  SIZE
    docker.io/library/alpine  latest  ...  ~8 MB
  Why:
    Full names (docker.io/library/...) skip Podman's 'which registry?'
    question.

--- Step 3 ----------------------------------------
Run a throwaway container. Jordan asks: "Is it a VM?" Prove it
shares our kernel.
  $ podman run --rm docker.io/library/alpine cat /etc/os-release
  $ uname -r
  $ podman run --rm docker.io/library/alpine uname -r
  You should see:
    NAME="Alpine Linux" ...
    The same kernel version both times.
  Why:
    Different distro inside, same kernel. That's the container vs VM
    difference.

--- Step 4 ----------------------------------------
Run a test web server in a container and reach it from the server.
  $ podman run -d --name web -p 8080:80 docker.io/library/nginx:alpine
  $ podman ps
  $ curl -s localhost:8080 | grep title
  You should see:
    CONTAINER ID  IMAGE ... PORTS 0.0.0.0:8080->80/tcp  NAMES web
    <title>Welcome to nginx!</title>

--- Step 5 ----------------------------------------
Debug like a pro: read its logs, peek at its config, and inspect its
status.
  $ podman logs web | tail -3
  $ podman exec web cat /etc/nginx/conf.d/default.conf | head -5
  $ podman inspect web --format '{{.State.Status}} {{.NetworkSettings.Ports}}'
  You should see:
    nginx access lines (from your curl)
    server { listen 80; ...
    running map[80/tcp:[{0.0.0.0 8080}]]

--- Step 6 ----------------------------------------
Jump inside the container, look around, and get back out.
  $ podman exec -it web sh
  $ ps
  $ exit
  You should see:
    A / # prompt. ps shows only nginx processes. exit returns you to the host.

--- Step 7 ----------------------------------------
Stop it, find it in the list of stopped containers, and start it
again.
  $ podman stop web
  $ podman ps
  $ podman ps -a
  $ podman start web
  You should see:
    ps is empty. ps -a shows web as Exited. Then it's running again.

--- Step 8 ----------------------------------------
Build Jordan's landing page into our own image.
  $ cd ~/linuxlab2/container
  $ cat Containerfile
  $ podman build -t poolsite:1.0 .
  $ podman images | grep poolsite
  You should see:
    STEP 1/4: FROM ... STEP 2/4: COPY ...
    Successfully tagged localhost/poolsite:1.0

--- Step 9 ----------------------------------------
Run our image, and tag it as the latest version.
  $ podman run -d --name pool -p 8081:80 poolsite:1.0
  $ curl -s localhost:8081
  $ podman tag poolsite:1.0 poolsite:latest
  $ podman images | grep poolsite
  You should see:
    <h1>Pool Pros - running in a container</h1>
    Two tags, SAME image ID.
  Why:
    A tag is just another name for the same image.

--- Step 10 ----------------------------------------
Pass the shop name in as a setting (environment variable).
  $ podman run --rm -e SHOP=PoolPros docker.io/library/alpine sh -c 'echo Hello from $SHOP'
  You should see:
    Hello from PoolPros

--- Step 11 ----------------------------------------
Jordan needs data that survives restarts. Show him a volume.
  $ podman volume create pooldata
  $ podman run --rm -v pooldata:/data docker.io/library/alpine sh -c 'echo saved > /data/f.txt'
  $ podman run --rm -v pooldata:/data docker.io/library/alpine cat /data/f.txt
  $ podman volume inspect pooldata --format '{{.Mountpoint}}'
  You should see:
    saved  (the first container is gone, the data isn't)
    The path on the host where it's stored.

--- Step 12 ----------------------------------------
The API container and the website must talk to each other. Put them
on one network.
  $ podman network create poolnet
  $ podman run -d --name api --network poolnet docker.io/library/nginx:alpine
  $ API_IP=$(podman inspect api --format '{{.NetworkSettings.Networks.poolnet.IPAddress}}')
  $ echo $API_IP
  $ podman run --rm --network poolnet docker.io/library/alpine wget -qO- http://$API_IP | grep title
  $ podman network ls
  You should see:
    10.89.0.2 (or similar)
    <title>Welcome to nginx!</title>
    poolnet  bridge
  Why:
    Podman 4+ also lets you use the name: http://api. Podman 3.4 on
    Ubuntu 22.04 needs an extra plugin for names, so we use the IP.

--- Step 13 ----------------------------------------
Marcus explains why we never use --privileged unless we must. See
what it unlocks.
  $ podman run --rm docker.io/library/alpine mount -t tmpfs none /mnt
  $ podman run --rm --privileged docker.io/library/alpine sh -c 'mount -t tmpfs none /mnt && echo MOUNTED'
  You should see:
    mount: permission denied (are you root?)
    MOUNTED
  Why:
    --privileged hands out extra powers. Avoid it unless you truly need
    it.

--- Step 14 ----------------------------------------
Ship it! Then clean up everything from testing.
  $ podman rm -f web pool api
  $ podman network rm poolnet
  $ podman volume rm pooldata
  $ podman image prune -a -f
  $ podman ps -a
  $ podman images
  You should see:
    Both lists are empty (or nearly).

STUCK?
  * Error pulling: Forbidden / connection refused
      The registry is blocked on this network. You can still do the build
      lab with a local base: sudo apt install -y busybox-static, then use
      FROM scratch and COPY /bin/busybox.
  * Port 8080 already in use
      Pick another: -p 8090:80
  * Error: name 'web' is already in use
      Remove the old one: podman rm -f web
  * 'short-name' prompt asks which registry
      Pick docker.io, or always use full names like
      docker.io/library/alpine.
  * Want Docker instead?
      Same commands work: sudo apt install -y docker.io, then sudo docker
      ... instead of podman ...

  Landing page shipped as a container, with volumes, networks and
  security understood.
